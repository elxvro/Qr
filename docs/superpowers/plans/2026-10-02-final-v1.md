# ELXVRO Scan Final v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Complete the existing ELXVRO Scan roadmap from v0.5 through stable v1.0 and ship one verified APK.

**Architecture:** Keep the existing native Kotlin/View architecture and current CameraX + ML Kit + ZXing stack. Add pure Kotlin logic for searchable/sortable history and scan deduplication, then wire final UX, feedback settings, onboarding, privacy/about, performance safeguards and Play-ready metadata into the current activity without introducing a server dependency.

**Tech Stack:** Kotlin, Android Views, CameraX, ML Kit Barcode Scanning, ZXing, SharedPreferences, JUnit 4, GitHub Actions.

**Spec:** Existing project roadmap established in conversation.

## Global Constraints
- Scanning remains local/offline; no INTERNET permission.
- Scanner remains portrait-oriented.
- Existing QR/barcode scanning, gallery scanning, QR generation, history/favorites and smart actions must remain functional.
- Final application version is 1.0.0.
- Deliver only the final APK to the user.

## Review Focus
- Repeated frames from the same code must not cause duplicate dialogs/history spam.
- History search must be case-insensitive and work across value, format and kind.
- History ordering must support newest-first and oldest-first.
- Camera denial must still leave gallery scanning usable.
- Sound/vibration settings must not break scanning when disabled.
